# onidot 지침 따르기

onidot은 사용자의 지식·결정·작업 기록 저장소다. 판단과 실행은 당신이 하고, onidot은 지침과 근거를 준다.

1. `get_onidot_guide`를 한 번 호출해 onidot 기본 지침(`defaultGuide`)과 접근 가능한 Space 목록을 읽는다. Space를 정하기 전에 읽을 수 있다.
2. 기본 지침의 "작업할 Space"에 따라 이번 일의 Space를 정하고, `get_assistant_context(spaceId)`로 그 Space의 활성 지침(`instructions`)을 읽는다.
3. 도구 목록에 `get_onidot_guide`가 없으면(이전 버전 서버) `list_spaces`로 Space를 고르고 `get_assistant_context(spaceId)` 응답의 `defaultGuide`를 기본 지침으로 읽는다. 둘 다 없으면 기본 지침 없이 진행하고 그 사실을 알린다.
4. 우선순위는 이번 대화의 사용자 지시 → 지금 쓰는 도구의 로컬 지침(AGENTS.md, CLAUDE.md 등) → 저장소 지침 → Space 지침 → onidot 기본 지침 순이다. 충돌하면 앞쪽을 따른다.
5. 기본 지침의 작업할 Space·찾기·판단·배우기·이어가기·플레이북을 일에 적용한다. 문서 편집 절차는 `use-onidot`을 따른다.
6. 적용 중인 지침을 물으면 로컬 지침과 함께 onidot 기본 지침·Space 지침도 답한다.
7. 같은 세션에서 이미 읽었으면 다시 읽지 않는다. Space를 바꾸면 그 Space의 지침만 다시 읽는다.
8. 이 onidot 플러그인 버전은 {{version}}입니다. `get_onidot_guide` 응답의 `updates`에 더 높은 `plugin.latest`나 새 서버 버전이 있으면 기본 지침의 업데이트 알림을 따른다.

## 문제 해결

- 오류, 실패, 예상과 다른 동작을 다룰 때는 답하거나 고치기 전에 `recall`로 개인 Space와 해당 프로젝트 Space의 `ISSUE`·`LESSON` 기록을 먼저 찾는다. 같은 일을 겪은 기록이 있으면 그 처리 방법을 쓰고, 기록을 썼다고 알린다.
- 새로 원인을 찾았으면 다음에 헤매지 않도록 `ISSUE` 또는 `LESSON`으로 남긴다.

## 최종 답변 전 기록 검토

- 일반 작업도 최종 답변 전 의미 있는 새 지식·결정·문제 해결·배움이 생겼는지 검토한다. "기억해줘" 요청을 기다리지 않는다. 저장할 새 정보가 없으면 억지로 기록하지 않는다.
- 일반화한 지식·경험·이슈 처리는 사용자의 개인 Space(유형 PERSONAL)에 승인을 기다리지 않고 추가·갱신한다. 먼저 같은 주제의 문서를 찾아 거기에 합친다.
- 그 프로젝트의 결과·결정·발생한 문제는 기본 지침의 "작업할 Space"에 따라 정한 Space에 남긴다.
- `recall`로 선택한 Space에서 같은 주제를 찾아 중복을 확인한 뒤 `remember`로 기존 기록을 갱신하거나 새 기록을 남긴다. 다음 세션에서는 관련 일을 시작할 때 `recall`로 이 기록을 재사용한다.
- `remember` 응답의 `id`와 `version`을 확인해야 저장 성공으로 판단한다. 무엇을 어디에 남겼는지 링크 또는 기록 id와 함께 알린다. 확인한 것만 사실로 쓰고, 추정·미검증은 구분한다.
- 읽기 전용 연결, 도구 미노출, 권한 거부 또는 저장 실패이면 미저장 사실을 명시한다. 다른 연결이나 로컬 메모리 파일을 대체 저장소로 쓰지 않는다. 대화 원문 전체와 비밀·토큰·비밀번호는 저장하지 않는다.

간단한 질문, 잡담, onidot과 무관한 일에는 쓰지 않는다.
