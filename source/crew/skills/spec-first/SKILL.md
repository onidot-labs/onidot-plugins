# spec-first

만들거나 맡기기 전에 "무엇이 되면 맞는가"를 먼저 정한다. 이미 정해진 것이 있으면 그것이 기준이다.

## 1. 기준 찾기

1. 연결된 지식 저장소, 저장소 문서, 이슈에서 이 일의 명세와 이전 결정을 찾는다. 제품 기획·설계 정본, 개발 순서 문서의 해당 항목, 결정 기록을 본다. 항목 이름(예: 단계 ID)만 아는 경우 그 이름으로 검색해 정의가 있는 문서까지 따라간다.
2. 같은 주제의 기존 조사·AI 기록을 찾는다(onidot이면 `recall`과 문서 검색). 이미 있는 조사는 다시 하지 않고 무엇이 바뀌었는지만 확인한다.
3. 찾은 문서는 **원문을 직접 읽는다.** 다른 문서의 요약, 인계 문서의 한 줄, 기억으로 옮겨 적지 않는다. 요약에는 "기준 경험은 무엇이다" 같은 핵심 문장이 빠지기 쉽다.
4. 기존 시험과 코드 주석에서 현재 의도된 동작을 확인한다.
5. 찾은 명세가 현재 코드나 다른 결정과 어긋나면 어느 쪽이 맞는지 확인한다. 추측으로 고르지 않는다.

## 2. 기준 묶음 만들기

찾은 것을 아래 묶음으로 정리한다. 계획·위임·검토는 이 묶음을 그대로 넘긴다.

| 항목 | 내용 |
| --- | --- |
| 기준 문서 | 링크와 판본(revision). 여러 개면 우선순위 |
| 핵심 문장 | 결과를 좌우하는 원문 문장을 그대로 인용한다. 필수 요소 목록이 있으면 목록째 |
| 기존 조사 | 같은 주제의 조사·기록 링크와 결론 한 줄 |
| 확인하지 못한 것 | 찾았지만 못 읽은 것, 찾지 못한 것 |

찾아봐도 기준이 없으면 "찾아본 곳"을 적고 3절로 간다. 묶음이 비었다고 기준이 없다고 단정하지 않는다.

## 3. 없으면 짧게 만든다

| 항목 | 내용 |
| --- | --- |
| 목표 | 이 변경으로 무엇이 가능해지거나 고쳐지는가 |
| 범위 | 바뀌는 동작과 영향받는 부분 |
| 비목표 | 이번에 일부러 건드리지 않는 것 |
| 수용 기준 | 확인 가능한 문장. "~하면 ~된다" 형태 |

- 수용 기준은 시험으로 옮길 수 있어야 한다. "잘 동작한다"는 기준이 아니다.
- 경계 조건과 실패 경우를 최소 하나씩 넣는다.
- 명세는 연결된 지식 저장소가 있으면 그곳에 둔다.

## 4. 기준에서 끌어내기

- 계획의 단계와 완료 기준은 수용 기준에서 나온다. `onidot-crew:plan` 스킬로 넘긴다.
- 시험은 수용 기준마다 하나 이상 만든다. `onidot-crew:tdd` 스킬로 넘긴다.
- 검증 때 이 수용 기준을 그대로 쓴다. `onidot-crew:verify` 스킬로 넘긴다.
- 위임 지시의 근거 칸에 기준 묶음을 넣는다. `onidot-crew:delegate` 스킬로 넘긴다.
- 결과를 받으면 기준 묶음의 핵심 문장과 대조한다. 결과가 기준과 다르면 결과를 받아들이기 전에 사용자에게 근거와 함께 묻는다. 메인이 "이쪽이 낫다"고 보더라도 기준을 말없이 바꾸지 않는다.

## 5. 무게 조절

| 변경 | 명세 |
| --- | --- |
| 한두 줄 버그 수정 | 수용 기준 한두 문장. 별도 문서 없이 위임 지시나 커밋 설명에 둔다 |
| 기능 하나 | 짧은 변경 명세 |
| 여러 모듈, 되돌리기 어려운 변경 | 변경 명세와 승인 |
| 설계·화면·계획·조사를 맡기는 일 | 기준 묶음(1·2절). 진단·제안만 하는 일이라도 생략하지 않는다 |

작은 수정에 별도 문서나 재승인을 강제하지 않는다. 오타·서식처럼 결과가 하나뿐인 편집에는 이 스킬을 쓰지 않는다.


## 서브에이전트로 실행 중일 때

역할 에이전트 안에서 이 스킬을 쓸 때는 사용자에게 묻기, 문서 저장, 승인 요청, 다른 역할에 맡기기를 직접 하지 않는다. 그런 단계는 반환에 '메인이 할 일'로 적는다. 이 스킬이 지금 자기 역할에게 맡기라고 하면 직접 수행한다.

## 점검 목록

- [ ] 기존 명세·결정·조사를 먼저 찾았고 원문을 직접 읽었다.
- [ ] 기준 묶음(링크·판본·핵심 문장·기존 조사)을 만들었다.
- [ ] 수용 기준이 확인 가능한 문장이다.
- [ ] 비목표를 적었다.
- [ ] 계획과 시험이 수용 기준과 연결된다.
- [ ] 변경 크기에 맞는 무게로 썼다.
