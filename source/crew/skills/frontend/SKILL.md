# frontend

새로 그리기 전에 이미 있는 것을 찾는다. 확인은 실제 화면으로 한다.

## 1. 먼저 찾기

1. 디자인 토큰: 색, 간격, 글꼴, 그림자, 반경.
2. 공용 컴포넌트: 버튼, 입력, 목록, 모달, 레이아웃.
3. 비슷한 기존 화면: 같은 패턴이 이미 구현된 곳.

있으면 재사용한다. 없을 때만 새로 만들고, 새로 만든 것도 기존 토큰을 쓴다. 임의의 색이나 간격 값을 하드코딩하지 않는다.

## 2. 재사용 요청일 때

"이 화면처럼", "이 컴포넌트를 써서" 같은 요청이면 아래를 보존한다.

| 보존할 것 | 예 |
| --- | --- |
| 구조 | 영역 배치, 계층 |
| 크기 | 너비, 높이, 여백 |
| 격자 | 열 수, 정렬 기준 |
| 스크롤 | 어느 영역이 스크롤되는가 |

부품을 몰래 바꾸지 않는다. 다른 부품이 낫다고 판단되면 바꾸기 전에 이유와 함께 알린다.

## 3. 반응형

- 좁은 화면, 보통 화면, 넓은 화면에서 모두 본다.
- 긴 텍스트, 빈 상태, 많은 항목에서 깨지지 않는지 본다.
- 가로 스크롤이 생기지 않게 한다. 의도한 경우는 예외다.

## 4. 접근성

- 의미에 맞는 요소를 쓴다. 클릭할 수 있는 것은 버튼이나 링크다.
- 키보드만으로 조작할 수 있고, 초점이 보인다.
- 이미지에 대체 텍스트, 입력에 레이블이 있다.
- 글자와 배경의 대비가 충분하다.

## 5. 확인

- 가능하면 브라우저로 열어 스크린샷을 찍어 확인한다.
- 상호작용(열기, 닫기, 제출, 오류)을 직접 해 본다.
- 확인하지 못했으면 "화면 확인 못 함"이라고 보고한다. 코드만 보고 된다고 하지 않는다.
- 큰 화면 작업은 designer에게 맡긴다.


## 서브에이전트로 실행 중일 때

역할 에이전트 안에서 이 스킬을 쓸 때는 사용자에게 묻기, 문서 저장, 승인 요청, 다른 역할에 맡기기를 직접 하지 않는다. 그런 단계는 반환에 '메인이 할 일'로 적는다. 이 스킬이 지금 자기 역할에게 맡기라고 하면 직접 수행한다.

## 점검 목록

- [ ] 기존 토큰과 컴포넌트를 먼저 찾았다.
- [ ] 재사용 요청이면 구조·크기·격자·스크롤을 보존했다.
- [ ] 부품을 몰래 바꾸지 않았다.
- [ ] 화면 크기별로 확인했다.
- [ ] 키보드 조작과 레이블을 확인했다.
- [ ] 스크린샷으로 확인했거나, 못 했다고 보고했다.
