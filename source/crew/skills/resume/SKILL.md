# resume

세션은 끊긴다. 일은 이어져야 한다. 진행 기록이 그 다리다.

## 1. 시작할 때

1. 연결된 지식 저장소(onidot)가 있는지 확인한다.
2. 있으면 이 일의 진행 기록을 찾는다. onidot이면 태그 `진행`이 붙은 AI 기록(NOTE)을 검색한다.
3. 가장 최근 기록을 읽고 목표·남은 일·다음 행동을 확인한다.
4. 기록이 가리키는 근거(경로, 링크, 커밋)가 지금도 맞는지 확인한다. 기록은 낡을 수 있다.
5. 저장소가 연결되지 않았으면 그 사실을 사용자에게 알린다. 다른 곳에 몰래 대체 저장하지 않는다.

## 2. 남길 때

작업 단위가 끝날 때, 그리고 중간에 멈출 때 남긴다.

| 항목 | 내용 |
| --- | --- |
| 목표 | 이 일이 끝나면 무엇이 되어 있어야 하는가 |
| 한 일 | 이번에 끝낸 것. 커밋·변경 경로 포함 |
| 남은 일 | 아직 안 된 것, 막힌 것과 이유 |
| 근거 링크 | 계획서, 결정 문서, 경로, 로그 위치 |
| 다음 행동 | 이어받는 사람이 바로 할 첫 행동 하나 |

- onidot이면 AI 기록(NOTE)으로 쓰고 태그 `진행`을 붙인다.
- 같은 일의 기존 기록이 있으면 새로 흩뿌리지 말고 이어서 쓴다.
- 큰 계획서 내용을 옮겨 적지 않는다. 링크만 남긴다.

## 3. 남기지 않는 것

- 비밀값: 토큰, 비밀번호, 키, 개인정보. 파일 이름과 위치만 쓴다.
- 대화 전체나 긴 로그 원문. 결론과 위치만 쓴다.
- 확인하지 않은 추측. 추측이면 추측이라고 표시한다.

## 4. 좋은 다음 행동의 예

- 나쁨: "나머지 마무리"
- 좋음: "`/repo/src/auth/session.ts`의 만료 처리 시험이 실패한다. 실패 로그는 기록 하단 링크. 원인 가설은 시계 주입 누락이다. `onidot-crew:debugging` 스킬로 확인부터 한다."

## 점검 목록

- [ ] 시작할 때 진행 기록을 찾아 읽었다.
- [ ] 기록의 근거가 지금도 맞는지 확인했다.
- [ ] 다섯 항목을 모두 채웠다.
- [ ] 비밀값과 대화 전체를 남기지 않았다.
- [ ] 저장소가 없으면 그 사실을 알렸다.
