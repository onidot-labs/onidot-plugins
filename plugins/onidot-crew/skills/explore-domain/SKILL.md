# explore-domain

낯선 일은 만들기 전에 이해한다. 이해의 깊이는 일의 성격에 비례한다.

## 1. 이미 있는 지식부터

1. 연결된 지식 저장소에서 관련 결정·기록·설계를 찾는다.
2. 저장소 문서, 지침 파일, 기존 코드의 이름과 시험을 본다.
3. 그래도 모르는 것만 새로 조사한다. 넓은 조사는 `onidot-crew:research` 스킬을 쓴다.

## 2. 조사할 것

| 항목 | 질문 |
| --- | --- |
| 업무 흐름 | 일이 어떤 순서로 흘러가는가 |
| 관련자 | 누가 쓰고, 누가 결정하고, 누가 영향을 받는가 |
| 입력과 출력 | 무엇이 들어오고 무엇이 나가는가 |
| 규칙 | 지켜야 할 업무 규칙, 제약, 규정 |
| 예외 | 흔하지 않지만 반드시 처리해야 하는 경우 |
| 숨은 전제 | 요청에 적히지 않았지만 당연하게 여겨지는 것 |

## 3. 사실·가정·미결정 나누기

- **사실**: 근거가 있다. 출처를 붙인다.
- **가정**: 근거는 없지만 합리적이다. 가정이라고 표시한다.
- **미결정**: 정해지지 않았고, 결정에 따라 결과가 달라진다.

섞어 쓰지 않는다. 가정을 사실처럼 쓰면 계획 전체가 기운다.

## 4. 질문하기

- 결과를 바꾸는 미결정만 묻는다. 결과가 같으면 기본값을 정하고 밝힌다.
- 질문마다 근거와 추천안을 붙인다. 열린 질문보다 선택지가 낫다.
- 질문은 모아서 한 번에 묻는다.

## 5. 깊이 정하기

| 일의 성격 | 깊이 |
| --- | --- |
| 작은 수정, 익숙한 분야 | 관련 기록 확인 정도 |
| 새 기능, 낯선 업무 | 흐름·규칙·예외까지 |
| 되돌리기 어려운 일, 여러 관련자 | 관련자와 숨은 전제까지 모두 |

## 6. 결과물

조사 결과를 짧게 정리해 `onidot-crew:plan` 스킬과 scoper에게 넘긴다. 사실·가정·미결정 세 묶음과 질문 목록이면 충분하다.


## 서브에이전트로 실행 중일 때

역할 에이전트 안에서 이 스킬을 쓸 때는 사용자에게 묻기, 문서 저장, 승인 요청, 다른 역할에 맡기기를 직접 하지 않는다. 그런 단계는 반환에 '메인이 할 일'로 적는다. 이 스킬이 지금 자기 역할에게 맡기라고 하면 직접 수행한다.

## 점검 목록

- [ ] 이미 있는 지식을 먼저 찾았다.
- [ ] 사실·가정·미결정을 나눴다.
- [ ] 결과를 바꾸는 결정만 물었고, 추천을 붙였다.
- [ ] 깊이가 일의 성격에 맞다.
