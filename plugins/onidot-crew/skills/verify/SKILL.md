# verify

완료는 말이 아니라 증거로 판정한다.

## 1. 원칙

- 서브에이전트의 '완료' 보고만으로 완료 처리하지 않는다.
- 시험 결과는 메인이 로그의 통과·실패 줄을 직접 보고 확인한다. 요약 숫자만 믿지 않는다.
- 기준을 낮춰 통과시키지 않는다. 기준을 바꿔야 하면 사용자에게 이유와 함께 묻는다.
- 실행하지 못한 확인은 통과로 적지 않는다. 미검증으로 적는다.

## 2. 역할

| 확인 | 역할 |
| --- | --- |
| 시험·린트·타입 검사·빌드 실행과 증거 수집 | qa |
| 변경이 요청·규약에 맞는지 검토 | reviewer |
| 완료 주장 전체의 최종 감사 | gate |

판정은 메인이 한다. 역할들은 증거를 모으고 의견을 낸다.

## 3. 절차

1. 완료 기준을 목록으로 펼친다. 계획과 `onidot-crew:spec-first` 스킬의 수용 기준에서 가져온다.
2. 기준마다 어떤 증거가 있으면 충족인지 정한다. 명령 출력, 시험 이름, 스크린샷, 파일 경로 등.
3. qa에게 필요한 명령을 맡기고 로그를 받는다.
4. 로그에서 통과·실패 줄을 직접 확인한다. 건수가 보고와 맞는지 본다.
5. reviewer에게 변경 검토를 맡긴다. 지적이 있으면 고친 뒤 그 지적과 영향 범위만 다시 확인한다.
6. gate에게 완료 주장과 증거를 넘겨 최종 감사를 받는다. 계획 단계가 3개 이상이었거나 여러 역할이 나눠 한 일이면 생략하지 않는다. 작은 일에서 생략했다면 보고에 생략했다고 쓴다.

## 4. 보고 형식

| 구분 | 내용 |
| --- | --- |
| 완료 | 기준과 증거(명령, 결과 줄, 경로) |
| 미완료 | 기준과 남은 일 |
| 미검증 | 확인하지 못한 기준과 이유, 확인할 방법 |

결과를 먼저 쓴다. 배경은 그다음이다.

## 점검 목록

- [ ] 완료 기준마다 증거가 있다.
- [ ] 시험 로그의 통과·실패 줄을 직접 봤다.
- [ ] 기준을 낮추지 않았다.
- [ ] reviewer와 gate를 거쳤다.
- [ ] 완료·미완료·미검증을 나눠 보고했다.
