# plain-writing

읽는 사람이 한 번에 이해하게 쓴다.

## 1. 원칙

- 결론을 먼저 쓴다. 배경은 그다음이다.
- 짧은 문장을 쓴다. 한 문장에는 한 생각만 담는다.
- 구체적인 말을 쓴다. "개선했다"보다 "응답 시간을 2초에서 0.3초로 줄였다".
- 기존 문서가 있으면 그 문체, 용어, 형식을 따른다.

## 2. 피할 것

| 피할 것 | 대신 |
| --- | --- |
| 군더더기("~하는 것이 가능하다") | "~할 수 있다" |
| 과장("획기적으로", "완벽하게") | 측정한 사실 |
| 굵은 글씨 남발 | 정말 놓치면 안 되는 한두 곳만 |
| 모든 것을 목록으로 | 이어지는 생각은 문장으로 |
| 표 칸에 긴 설명 | 표는 열거 가능한 사실에만 |
| 수동태와 주어 생략으로 흐린 책임 | 누가 무엇을 하는지 쓴다 |

## 3. 약어와 ID

- 약어, 작업 ID, 내부 이름은 처음 나올 때 풀어 쓴다.
- 예: "M1(서버 단일화 작업)", "PR #15(로그인 수정)".
- 읽는 사람이 모를 수 있는 용어는 한 줄로 설명한다.

## 4. 사실과 추측

- 확인한 것과 추측한 것을 구분해 쓴다.
- 확인하지 못한 것을 그럴듯하게 채우지 않는다. 비었다고 쓴다.
- 경로, 명령, 숫자는 실제로 확인한 값을 쓴다.

## 5. 구조

- 제목만 읽어도 흐름이 보이게 한다.
- 절차는 번호 목록, 순서 없는 나열은 글머리표를 쓴다.
- 같은 내용을 두 곳에 쓰지 않는다. 한 곳에 두고 가리킨다.

## 점검 목록

- [ ] 첫 문단에 결론이 있다.
- [ ] 한 문장에 한 생각이다.
- [ ] 과장과 군더더기를 지웠다.
- [ ] 굵은 글씨와 목록을 남발하지 않았다.
- [ ] 약어와 ID를 처음 나올 때 풀어 썼다.
- [ ] 확인하지 않은 것을 사실처럼 쓰지 않았다.
- [ ] 기존 문서의 문체를 따랐다.
