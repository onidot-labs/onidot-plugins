# run

승인된 계획을 묶음 단위로 실행한다. 메인은 맡기고, 확인하고, 병합한다.

## 1. 역할 고르기

| 단계의 무게 | 역할 |
| --- | --- |
| 작고 분명한 구현 | worker-quick |
| 일반 구현 | worker |
| 어렵고 응집된 구현, 판단이 필요한 구현 | worker-deep |
| 화면 | designer |
| 문서 | writer |

맡길 때는 delegate 스킬의 위임 틀을 쓴다.

## 2. 동시 실행

- 수정 파일이 서로 겹치지 않는 단계만 동시에 맡긴다.
- 겹치거나 겹칠 수 있으면 순차로 맡긴다.
- 꼭 동시에 해야 하면 worktree로 격리한다. 병합은 메인만 한다.
- 서브에이전트는 백그라운드로 돌 수 있다. 완료 알림이 오기 전에 결과를 추측하거나 보고하지 않는다.

## 3. 단계 게이트

단계는 아래 다섯 관문을 모두 통과해야 닫는다.

1. **계획 정합.** 맡긴 범위대로 했는가. 범위 밖 변경이 없는가.
2. **자동 검사.** qa가 바뀐 범위의 시험·린트·빌드를 실행한다.
3. **실행 증거.** 로그의 통과·실패 줄, 출력, 스크린샷 같은 실제 증거가 있다.
4. **검토.** reviewer가 변경을 원래 요청과 대조한다. 한두 줄 수정은 생략할 수 있다.
5. **정리.** 임시 파일, 디버그 출력, 불필요한 변경이 남지 않았다.

## 4. 실패 처리

실패하면 아래 순서로 올린다.

1. 빠진 맥락을 보강해 다시 맡긴다.
2. 방향을 조정하는 메시지를 보낸다.
3. 단계 자체를 다시 쓴다.

같은 단계가 두 번 실패하면 advisor에게 자문한다. 성공한 단계는 다시 돌리지 않는다.

## 5. 마무리

- 모든 단계가 닫히면 verify 스킬로 완료 기준 전체를 확인한다.
- 진행 상황은 resume 스킬대로 남긴다. 멈출 때도 남긴다.
- 사용자 보고는 결과를 먼저 쓰고, 완료·미완료·미검증을 나눈다.

## 점검 목록

- [ ] 단계마다 무게에 맞는 역할을 골랐다.
- [ ] 동시에 맡긴 단계의 수정 파일이 겹치지 않는다.
- [ ] 완료 알림 전에 결과를 보고하지 않았다.
- [ ] 단계마다 다섯 관문을 통과했다.
- [ ] 두 번 실패한 단계는 advisor에게 자문했다.
- [ ] verify 스킬로 마무리했다.
